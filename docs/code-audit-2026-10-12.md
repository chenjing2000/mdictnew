# 代码审查、整改与清理

日期：2026-10-12。本次重新检查模块职责、内聚与耦合、查询和配置流程、浏览器资源及布局、测试、发布脚本和生成文件。保留此前确认的交互、界面和单文件发布方案。

## 模块设计结论

`WPF -> Application -> Core` 单向依赖合理，继续保留三层。Core 负责 MDX/MDD 格式与读取，Application 负责同步和本地资源回退，WPF 负责交互和展示。每个结果区拥有自己的读取服务和浏览器，资源不跨词典共享。

MainWindow 的输入、候选、历史和结果发布共享状态，无须拆成相互回调的管理器。配置存储与设置控件分开；Controller 管生命周期和宿主交互，ResourceHandler 管资源响应，三个桥接脚本各有明确职责。

没有新增接口层、依赖注入、通用基类或配置框架。保留少量短启动脚本、路径处理与解压流程重复，避免为减少几行代码增加抽象。异步、锁、候选与配置版本号，以及浏览器双击兼容子类均有实际用途，不能作为过度设计删除。

## 必要整改

1. **配置读取校验不一致。** 原来保存会拒绝重复路径和非 MDX 文件，但读取不会。手工编辑的非法配置可进入结果列表，后续操作又无法保存。读取复用已有路径校验，报告无效配置；仍允许已有文件暂时缺失，便于重新排序或删除。中文 UTF-8、顺序和立即保存规则保持不变。
2. **页面高度漏报。** 原来把视口变化同时发生的所有增长视作反馈，可能漏掉 CSS 内容变高。现在仅抑制上一条高度报告引起的视口增长；外部视口变化继续测量。保留 `vh/%` 防循环条件，没有引入 CSSOM 拦截框架。
3. **旧资源污染新页面统计。** 旧词条的延迟资源请求完成后，会更新已重置的新页面统计。异步读取前捕获已有页面编号，仅在页面仍有效时更新计数和错误；资源响应继续正常完成。

## 推荐级简化

精确查词原先先通过哈希表取得词条，再通过 `AllEntries.IndexOf` 线性寻找同一位置。增加普通的 `FindExactIndex` 方法，现有 `FindExact` 保持兼容，Core 查询和 CLI 直接复用位置。没有新增索引或缓存。重复词条仍返回首个匹配项，共享记录偏移保持原行为。

现有测试覆盖解析、资源隔离、状态竞争、保存失败和原生键鼠行为，具有明确回归价值。没有为缩减数量删除这些用例，也没有新增测试框架。索引断言并入既有用例，仅为三个已确认边界增加四项检查。
