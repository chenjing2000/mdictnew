# 代码审查、整改与清理

日期：2026-10-12。审查现有模块依赖、查词与候选状态、配置切换、解析边界、资源路由、浏览器生命周期、测试、启动/发布脚本及忽略规则。保留既定功能、界面、词典格式和配置格式。

## 设计判断

| 检查项 | 判断与处理 |
| --- | --- |
| 模块划分与耦合 | `WPF -> Application -> Core` 单向依赖合理。Core 不依赖窗口或浏览器；Application 统一读取锁与本地资源回退；WPF 处理交互和展示。保留三层。 |
| 内聚与函数归属 | 主窗口的输入、历史、候选和结果共享状态；结果区拥有各自的服务及浏览器；Controller 处理导航/消息；ResourceHandler 处理 URL、MIME 和响应。设置存储与设置控件分开，无须再拆管理器。 |
| 抽象与高级语法 | 没有自建接口层、DI、插件框架、通用基类或基于反射的业务调用。普通 LINQ、事件 lambda、局部命名元组及资源作用域写法服务于当前流程，改成多层类或手动管理资源不会更简单。测试中的反射仅用于检查内部状态。 |
| 过度设计与重复 | 保留少量路径标准化、解压和短启动脚本重复，避免通用框架。Header 的完整字节读取与现有 `MdictBinary.ReadBytes` 完全重叠，复用后删除私有重复方法。 |
| 逻辑与状态 | 保留候选防抖/版本号、配置版本号和读取锁；这些机制阻止旧结果回写和读取竞争，不能为减少代码而删掉。修正显示失败分支缺失的输入恢复。 |
| 格式与资源边界 | 保留块长度、文件边界、条目数量、校验和及编码检查；MDX 索引完整加载后才发布。各词典资源隔离，优先 MDD，未命中才读取同目录资源，拒绝路径越界与资源重解析点。 |
| 性能 | 精确键已有大小写不敏感映射；前缀搜索与部分记录位置定位仍线性扫描。修正文档中“精确查询全部线性”的不准确描述，未引入未经测量的索引或缓存。 |

## 必须修复的问题

内部链接查询取得 HTML 后，如果所有浏览器显示失败，`LookupAsync` 的 `loaded == 0` 分支只写错误提示。其它未命中及异常分支会恢复此前查询文字，这个分支遗漏了相同操作，留下用户正在编辑的无关文字。

修复只补上既有的 `!preserveInputOnFailure && previousWord.Length > 0` 条件和输入恢复。失败仍清空结果、不增加历史；手动查询失败仍保留新输入。

新增三个 WPF 检查：内部查询显示失败恢复旧词、结果留空且历史不变、手动显示失败保留编辑词。通过释放已初始化的 Controller 制造确定的显示失败，使用真实窗口与合成 MDX，不需要修改实际词典或浏览器安装。手动用例先重新成功显示旧词，确保输入恢复条件确实被检验。

## 建议级精简

- 删除无调用的 `DictionaryResultView.ShowError`、其始终隐藏的错误控件及相关隐藏操作。运行中的错误继续汇总到底部状态栏。
- 删除无调用的 `WebViewController.ShowMessageAsync` 及两个无用的 `System.Net` 引用。保留实际使用的 F9 诊断页。
- Header 复用完整字节读取工具，保留长度检查与 `InvalidDataException` 类型；文件截断提示统一为现有工具的文字。
- 修正三个桥接脚本注册处过时的“两个桥接”注释。

全项目调用及绑定检查、独立只读复查支持上述删除；没有删除 CLI、自测或集成测试使用的诊断接口。未统一重排、改名或为风格改写正确代码。
