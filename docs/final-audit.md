日期：2026-10-11。在此前整改和窗口外观更新的基础上，复查现有源码、调用关系、异步状态、释放逻辑、测试与生成文件。不增加功能，不修改词典格式、个人设置或既定界面。

## 设计结论

| 检查项 | 结论与处理 |
| --- | --- |
| 模块与功能划分 | `WPF -> Application -> Core` 单向依赖合理。解析、服务锁、窗口编排、浏览器导航、资源响应各有边界；保留。 |
| 内聚与函数归属 | 历史和候选依赖主窗口共同状态；结果区拥有自己的服务与浏览器；设置存储独立于控件；不再拆管理器。 |
| 耦合 | Core 不引用 WPF/WebView2。浏览器通过事件请求窗口查词，不直接修改统一历史；各词典资源隔离。 |
| 语法与抽象 | 未引入 DI、插件框架或通用基础类。异步、锁、事件、版本号用于实际生命周期与并发需求；不能为了语法简单而删除。 |
| 冗余与重复 | 移除四个无调用成员及一个未使用引用。短小路径处理、启动脚本的少量重复保留，避免增加公共框架。 |
| 清晰度 | 简单 LINQ、局部三字段命名元组、格式数据类保留；没有证据支持全面改写或纯风格重排。 |
| 性能 | 继续保留现有线性查询及按需索引；未测出新的瓶颈，不加入索引系统或缓存层。 |

更详细的模块职责与数据流见 [architecture.md](architecture.md)。

## 正确性整改

未配置可用词典时，F9 创建临时浏览器。如果首次初始化失败，旧实现仍保留该对象；下次跳过初始化，不能正常重试。

先用进程级 `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER` 指向不存在的目录重现问题，随后恢复环境变量。旧实现的“释放失败对象”和“恢复后重试”两项检查均失败。修改为初始化失败时释放、移除并清空临时结果区，保留原错误提示；重试可以重新创建浏览器。

另外检查词典已配置但全部打开失败的情况：恢复空状态提示必须依据实际配置，不能显示“尚未设置词典”。该检查先失败，随后通过。只改变失败恢复路径，正常查询、内存历史和启动留空不变。

## 精简成员

全源码及测试引用检查确认以下成员没有调用，已移除：

- `DictionaryService.DictionaryName`、`MddCount`，以及因此不再需要的 `System.IO` 引用。
- `WebViewController.GetDomResourceStateAsync`、`LastResourceError`。

没有删除仍用于 CLI、自测或集成检查的诊断功能、Core 格式类型和关闭状态检查。

现有 `.gitignore` 规则满足需求，保留并用临时 Git 仓库执行 40 项正反例检查：27 项构建、缓存、词典或临时文件被忽略，13 项源码、脚本、历史文档和合法图片/HTML/音频保留。不全局忽略资源扩展名，也不初始化项目 Git 仓库。
