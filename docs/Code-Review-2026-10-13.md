# 代码结构审查与整改（2026-10-13）

## 整体模块与职责

依赖保持 `WPF -> Application -> Core` 单向。Core 的 Header、Key、Record、MDD 读取器对应实际文件段；格式数据对象不依赖界面。DictionaryService 负责同步锁和资源回退，DictionaryResultView 拥有一个词典的服务与浏览器；MainWindow 编排输入、候选、查询与历史。WebViewController 处理导航和脚本消息，WebResourceHandler 处理资源响应，三个 JS 文件分别负责词条、音频和布局。这些职责有实际边界，不需要合并为通用框架。

MainWindow 虽然较长，但输入、历史、配置版本及结果发布使用共同状态。此轮保留窗口编排，避免拆成彼此回调的多个管理器。界面依赖 Application 的具体服务，是小程序可理解的耦合；二进制读取没有反向依赖界面。未新增接口、基类、依赖注入、反射框架或第三方包。

## 必须修复的正确性问题

候选搜索先过滤打不开的词典，再用过滤后的数组位置生成错误编号。前面存在失效路径时，后面的损坏词典被提示为错误的位置。

整改保留原始配置顺序的快照，用普通索引循环跳过不可用词典，并按原位置报告编号。仍在后台搜索、保留局部失败和旧结果版本检查，不影响候选的顺序、去重或响应性。新增回归用例使用“缺失词典、损坏词典、正常词典”顺序，修复前失败、修复后通过。

## 建议级简化

设置路径规范化由 `Where/Select/ToList` 连锁查询改为显式循环；重复检测改为明确的 HashSet 遍历。继续保留空值过滤、完整路径、不区分大小写去重、数量限制、扩展名及文件存在校验，并保持校验顺序。设置窗口四个操作仍使用同一个提交方法，因为它确实统一了保存成功后更新界面的行为。

普通属性、短小 LINQ、事件和局部元组继续保留；不把语言功能本身视为缺陷。异步、锁、资源请求 deferral、配置版本号以及导航完成事件承担响应性和关闭顺序，不可为了形式简单而删除。RIPEMD 与格式解压属于必要实现。

## 文件与忽略规则

`.gitignore` 补充崩溃转储、覆盖率报告和 Python 缓存；继续排除 bin/obj、发布目录、词典、配置、WebView2 缓存和测试输出。原始图标及 Logo.xaml 被图标生成工具使用，CMD 启动入口被 README 引用，均保留。历史审查和补丁是项目资料，保留在 docs/history，不作为当前维护入口。

清理仅针对确认可重建的编译与测试输出；不清空 dist，不删除配置、词典、媒体或迁移备份。四个程序没有抽取共享运行库，少量简单启动与文件处理重复继续保留。
