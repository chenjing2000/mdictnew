# 代码审查、整改与清理

日期：2026-10-10。范围：生产 C# / XAML、WebView2 控制与资源处理、三个 JS Bridge、CLI、测试、启动脚本、文档和生成文件。保持已经确认的多词典、统一历史、输入框焦点与设置页外观，不增加功能。

本文件保留首轮审查结果。文中的旧构建、发布和验证缓存已在后续整理中删除；最新结果见 [整体复查记录](final-audit.md)。

## 整体判断

现有模块依赖单向，Core 不依赖 UI；每个结果区独立拥有服务、浏览器和资源路由。模块职责与对象生命周期基本合理，未发现需要整体架构重写的证据。完整职责和数据流见 [architecture.md](architecture.md)。

没有新增接口、DI、基础类、通用配置框架或额外依赖。必要的异步、锁、事件和版本检查继续保留；普通集合操作和局部命名元组没有强制改写。避免为减少少量重复而建立更复杂的抽象。

## 必须修复的正确性与异常输入问题

| 问题 | 原因 | 整改及保持的行为 |
| --- | --- | --- |
| MDX 索引读取失败后再次查询出现空引用 | Key 已写入对象，但 Record 加载失败；后续误认为完成初始化 | 三部分先读入局部变量，全部成功后才提交索引。仍按需加载；失败后可重试，修复文件后可读取 |
| 有效命令行词典被损坏的保存配置阻止打开 | 启动先解析 JSON，再处理命令行覆盖 | 有效命令行路径先处理，不读取无关的保存配置；仅本次覆盖、不改写配置 |
| 特殊损坏头部解析耗时异常 | 现有属性正则在长标识符无等号时反复回溯扫描 | 保留匹配规则，使用 .NET 内置 `NonBacktracking` 模式；不新增自制解析器，也不强制要求所有历史词典头部为严格 XML |
| Key 块不可能的条目数量进入后续分配 / 解码 | 元数据数量与解压后字节数的最低约束未提前校验 | 条目数量不能超过块大小除以最低条目长度（MDX 9 字节、MDD 10 字节），在解码和容量分配前拒绝 |

上述问题均先构造失败用例，再验证修复。新增 Core 检查覆盖重复失败、文件修复后的重试、长异常头部与不可能的条目数量；WPF 检查覆盖命令行绕过损坏配置且不改写它。

## 建议级整改

- 多词典查询从嵌套 LINQ 分支改为显式循环，仍逐词典收集 HTML / 错误，不改变局部失败规则。
- 删除无用的长期 Header 字段，避免保留没有读取者的状态。
- 导航按钮更新方法改为描述前进和后退的名称，并修正旧注释。
- 资源响应的纯转发重载合并为默认参数，调用点与响应内容保持不变。
- 三个 CMD 启动脚本选择与项目兼容的用户目录 SDK，保留失败退出码。原 PATH 中的 SDK 8 无法满足当前项目；没有修改系统 PATH。

不做纯风格重排，不为局部三字段结果新建类，不把窗口编排拆成多个互相调用的管理器。Core 线性搜索的进一步优化属于测量后的工作，本次没有扩大范围。
