# 单文件发布、运行时与用户配置

日期：2026-10-12。本文件记录当前实施的发布方案；历史文档中的文件夹发布和 AppData 配置路径属于旧行为。

## 发布与依赖

执行根目录 `tools/Publish.ps1`，输出 `dist/MdictViewer/MdictViewer.exe`。分发时只需提供这个 EXE；首次使用设置后，目录中还会有用户自己的 `dictionaries.json`。本次产物约 24.6 MiB。

发布参数为 `-c Release -r win-x64 --self-contained false`、`PublishSingleFile=true`、`IncludeNativeLibrariesForSelfExtract=true`。不启用裁剪，不发布 PDB 或 XML 文档。应用 DLL 和 WebView2 托管组件、原生加载器包含在 EXE 中；原生加载器由 .NET 在运行时解压到缓存。这是分发单文件，不代表运行时完全不生成临时文件。

脚本先发布到临时目录，确认输出确实只有 EXE，再替换正式产物；构建或产物检查失败保留旧发布。成功后删除旧文件夹发布的已知 DLL、元数据、旧浏览器缓存目录及三个应用项目的 `bin`，保留配置、其他用户文件和 `obj`。正在运行的 EXE 应先关闭。

运行需要 Windows x64、.NET 10 Desktop Runtime x64 和 WebView2 Runtime，不需要 .NET SDK。程序不捆绑、不下载、不安装这两种运行时。

- 缺少 .NET：托管代码无法运行，由 .NET 原生启动器显示安装提示和下载入口。安装时选择 .NET 10 **Desktop Runtime x64**，以满足 WPF 桌面框架要求。
- 缺少 WebView2：主窗口显示安装提醒和“下载 WebView2”链接，链接打开官方页面；用户安装后重新启动程序。每次初始化浏览器也会检查运行时，失败后可以重试。
- WebView2 用户数据保存在 `%LocalAppData%/MdictViewer/WebView2`，与配置位置分开，不在 EXE 旁创建 `MdictViewer.exe.WebView2`。

官方说明：[.NET 单文件发布](https://learn.microsoft.com/en-us/dotnet/core/deploying/single-file/overview)、[.NET 启动失败排查](https://learn.microsoft.com/en-us/dotnet/core/runtime-discovery/troubleshoot-app-launch)、[WebView2 分发](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/distribution)。

## 配置生命周期

配置固定为 EXE 同目录的 `dictionaries.json`，使用 `AppContext.BaseDirectory` 定位，启动工作目录不会影响它。

1. 启动时只读取已有配置；不存在时保持空词典列表，不创建文件。
2. 首次点击设置，先以“不覆盖已有文件”的方式创建 `[]`，再打开词典列表窗口。目录不可写或创建失败时，在主窗口显示错误。
3. 每次添加、上移、下移、删除先写配置，成功后更新列表；失败显示错误并保持列表原样。关闭或 Esc 不撤销已保存操作。已有文件即使格式损坏，也不会因打开设置而被初始化覆盖。
4. 新选择的文件必须是已存在的 MDX；保存校验最多 8 项、重复和路径格式，通过临时文件替换配置。已有失效路径仍可移动或删除，空列表合法。

格式为 JSON 字符串数组，保存的是 MDX 绝对路径，按列表顺序排列。明确使用无 BOM UTF-8；序列化允许中文直接输出，不显示为 Unicode 转义。无需旧格式迁移或专门兼容层。例如（仅为格式示例，不是程序默认值）：

```json
[
  "D:\\Dictionaries\\Example.mdx"
]
```

所有外部词典位置均来自配置，或本次启动显式传入的命令行 MDX 路径。命令行不自动写入配置。词典标题取文件名；配套 MDD 按所选 MDX 的同目录同名 `.mdd`、`.数字.mdd` 规则发现，不固定名称或分卷数量。MDD 未命中的资源仍可从该 MDX 同目录或子目录读取，沿用现有路径安全校验。

本次未增加相对路径规则、自动词典扫描、默认词典列表、运行时自动安装或新的配置框架。现有 `OxfordDictionary` 等类型名称保留兼容，其读取对象由传入的 MDX 路径决定；名称不表示内置某个外部词典，也不承诺支持所有 MDict 变体。

## 设置列表

设置窗口使用单选列表，仅显示 MDX 文件名（含扩展名）；完整路径留在内存和配置中，不提供路径编辑、文本复制或横向查看。窗口默认 450×320，最小 420×300，最大 500×500（均为 WPF 逻辑像素，仍受屏幕工作区限制）；原生最大化按钮禁用，保留拖动边缘缩放。窗口字号统一为 14。列表项上下内边距由 10 缩为 6；按钮由 40×40 缩为 32×32，图标由 24×24 缩为 19.2×19.2，间隔由 8 缩为 6。底部操作顺序固定为文件夹、上移、下移、减号四个图标按钮；文件夹提示文字为“选择词典文件”。无加号、逐行按钮、保存或取消按钮。内容左右外边距 10、底边距 8，按钮上方间距 6；错误提示保留在按钮下方，无错误时整行折叠，有错误时展开；成功操作后再次隐藏。

- 选择文件成功后追加到末尾并选中新项；取消文件选择不改变列表。
- 同一个文件按大小写不敏感的完整路径去重，重复时提示英文 warning“Warning: This dictionary is already in the list.”；同名但不同目录允许添加。
- 上下移动一次一位，保持选中。未选中时排序及删除禁用；首项禁用上移，末项禁用下移。
- 删除选中项后选中下一项；没有下一项则选中上一项。允许删除全部词典，不保留空白占位行。
- 最多 8 项，达到上限禁用文件选择。每次操作立即保存，窗口未关闭时主窗口的词典和结果保持不变。关闭后若有成功变更，一次性应用最终列表并重新查询当前已显示词；无变更不刷新，尚未查词时不自动查询输入内容，删除全部词典后清空结果与历史。

## 查询结果字号

主窗口不再设置最大宽高或工作区大小上限，保留 450×450 最小尺寸及 Windows 原生最大化行为；设置窗口的尺寸限制保持不变。词典标题行背景为 `#007175`，名称和三角形填充、描边统一为 `#ecebc2`；三角形按钮背景透明。

主窗口标题仅显示 `MdictViewer`。查询输入框最小宽度 100、高度 30、字号 15，上下内边距缩为 3；右侧三个按钮为 30×30，图标同步缩小，均使用 WPF 逻辑像素。未修改窗口外轮廓或设置窗口尺寸。

候选提示在输入框失焦、主窗口开始移动或缩放、查询或按 Esc 时关闭，并取消待处理的候选请求；方向键选择和鼠标点击候选正常工作。重新聚焦不自动显示，重新输入才启动候选查询。窗口移动/缩放开始使用原生消息关闭，不依赖输入框是否失焦，不维护额外的“动作识别”状态。

所有词典页面在共同 HTML 外壳中设置 `html,body{font-size:14px}`，同时提供正文继承与 rem 的基础大小。规则不使用 `!important` 或全元素覆盖，不修改外部词典文件；词典自己的明确字号、标题及相对大小层次继续生效，因此并不保证每个词典的所有文字大小完全相同。WPF 检查验证多词典基础字号、标题层次、明确指定的字号以及相对字号，保留现有缩放与页面高度处理。主界面的输入框取消默认上下文菜单，所有词典 WebView2 禁用默认上下文菜单；键盘输入与查询保持不变。

## 选词、复制与提示

- 在查询结果中拖选文字，松开左键时自动复制原选区文本，保留换行和中文，不执行查询。
- 普通双击使用浏览器默认选词，随后复制并通过主窗口统一流程查询所有配置词典；成功查询进入历史，未命中仍复制但不新增历史。复制失败会以英文 error 提示，查询仍可继续。
- 普通点击不复制旧选区；链接、音频、按钮、可编辑控件和带点击处理的词典控件保留原有交互，不触发上述手势。
- 两个窗口左上角图标的左击系统菜单被屏蔽，保留标题栏和窗口边缘的常规操作。
- 主窗口状态栏和设置错误提示每次更新后显示 6 秒，新消息重新计时。到期清空文字并折叠整个提示区域，主窗口运行时下载入口一并收起；设置提示始终位于四个按钮下方，成功操作立即隐藏错误。

## 配置位置与移动

旧版 `%LocalAppData%/MdictViewer/dictionaries.json` 不自动搬移或删除。需要沿用时，将它复制到新 EXE 同目录，或重新在设置中选择词典。移动 EXE 时一并携带配置；其中的绝对词典路径仍须有效。程序应放在用户可写的文件夹，才能在同目录初始化和保存配置。

## 验证记录

Core 28、WPF 128、Entry Bridge 18、Layout Bridge 10、独立资源 7、设置列表与中文保存 26，加上实际发布 EXE 9 项，共 226 项通过。WPF 测试可显式提供第二个真实 MDX，额外检查真实多词典读取。

本轮新增检查拖选复制不查询、双击复制与历史、未命中仍复制、两个原生窗口图标点击消息，以及两处提示计时重启和到期折叠。双击测试使用 Windows 原生鼠标按下/松开，经 WPF 控件转发，在 `before banana after` 中双击 `banana`，验证仅复制和查询该单词；测试结束恢复鼠标位置与剪贴板。拖选使用预置 DOM 选区与鼠标事件检查复制消息。未逐个验证所有第三方词典的自定义选区和点击脚本。

整行选区修复：当前 WebView2CompositionControl 的 OnMouseDown 与 OnMouseDoubleClick 会重复转发第二次按下，实际记录的浏览器点击次数为 1、2、3，造成整行选择且不触发 dblclick。仅在使用的控件子类中阻止 OnMouseDoubleClick 重复转发，保留原有 OnMouseDown/OnMouseUp 与浏览器默认单词选择。旧测试绕过 WPF，且元素只包含一个词，未覆盖此问题；新的原生多词句子测试在修复前失败，修复后通过。

实际发布测试将 EXE 单独复制到临时目录，从不同工作目录启动，验证启动不创建配置、首次设置创建同目录空数组、原生文件选择追加并立即保存、设置打开期间主窗口不变、关闭后刷新、中文配置和查词、原生 WebView2 加载器及嵌入脚本可用、缓存位置、缺少 WebView2 的下载入口和缺少 .NET 的原生提示。缺少 .NET 使用隔离的运行时目录模拟，未卸载机器已有运行时。

测试精简：设置验证集中在独立入口，使用空的临时 MDX 文件验证路径和列表，无须生成完整词典；WPF 仅保留与主窗口交互的设置验证。删除重复删除/数量检查、图标像素比例与控件外观数值检查、常规截图。异步关闭检查用服务锁控制发布顺序，替代五次重复和固定延迟。Core、路径安全、资源隔离、候选取消、浏览器失败重试以及实际发布 EXE 测试保留。按修改范围运行，发布前单独运行发布包验证。

验证环境：Windows，SDK 10.0.401，Desktop Runtime 10.0.12。未在没有预装依赖的实体新机器上验证，未覆盖 ARM64 / x86，也未扩展原有词典格式兼容范围。

信息栏仅显示英文 Warning / Error。正常启动、配置应用、查词成功、复制成功、无匹配结果、空输入和 F9 自测成功都不显示通知。异常采用操作说明及异常类型，避免本地化系统错误产生中文；多词典异常以配置顺序编号定位。原有六秒清除和正常操作后的收起行为保留。
